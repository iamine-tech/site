Incident-analysis agent · on a banking assignment

A first incident diagnosis without pulling in a developer

At a French retail bank, I designed an agent that reads the logs after a deployment and returns a short report: what is happening, the impact for the customer, and what needs doing.

By Amine Benmansour, application architect

The starting point

After a deployment to the test environment, someone has to read the logs, check the deployed version and say whether an error is new or already known. That first triage took a developer, even when the question came from a business analyst.

What the agent does

  • It searches the logs for errors over a chosen period, and compares their volume with the same window seven days earlier.
  • It reads the version actually deployed and compares it with the image registry.
  • It groups cases by correlation ID and links cascading errors across services.
  • It qualifies each error: technical or functional, known or new, with a green, amber or red status.
  • It translates all of this into business language and suggests an action, for the analyst or for the developer.

Three design rules

  1. Read-only. The agent fixes nothing: no rollback, no merge request, no configuration change. It suggests, a person decides.
  2. Evidence for every claim. A link to the search or a log extract; otherwise the agent writes “hypothesis” or “unknown”. Never “nothing to report” without reliable data.
  3. Business knowledge stays outside the agent. The rules live in files that analysts and developers extend themselves. An error missing from those files is marked “to be qualified”: the agent does not guess a rule.

What it does not do

It does not monitor continuously: it runs on demand, in the code editor. It does not analyse production until the masking of sensitive data is confirmed there. No card number or customer identifier appears in its output.

How it is built

A single agent, with a guided, jargon-free mode for business analysts. It relies on the coding assistant approved by the client, in agent mode, and on read-only MCP servers to the logs, the image registry, the code repository and the documentation.

It is distributed to the team through an editor extension. Built on my own initiative, it is used by the team.
