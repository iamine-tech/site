LCL · Crédit Agricole group

Dec 2025 – present

Senior Java engineer, application and data-flow architecture

Context

A card, transfer or cheque transaction flagged as suspicious must be confirmed by the customer on their phone, then processed without delay.

My role

Design and development, with the team, of the Java microservices behind this confirmation journey: Kafka flows with Avro contracts, REST APIs and mainframe exchanges.

Technical choices

Error recovery without duplicate effects: a Kafka retry strategy, a replayable dead-letter topic and a step-tracking table. Every successful step is recorded and never replayed.

A resilience pattern, documented and then presented to other teams, for Kafka consumers that chain several external calls.

A secure file-transfer component: Spring Batch, encryption, CFT.

Java 21 · Spring Boot 3 · Kafka · Avro · REST · CICS / CTG · PostgreSQL · Kubernetes · ArgoCD · GitLab CI · Dynatrace

BforBank · Crédit Agricole group

Jan 2023 – Sep 2025

Tech lead, card and tokenisation platform

Context

An online bank: card lifecycle and mobile payments, with the card processor and Visa in the loop, and response-time limits set by the network.

My role

Application architecture and development of the card lifecycle microservices (issuing, activation, blocking, PIN) and of Apple Pay and Google Pay tokenisation, using hexagonal architecture. Spring Boot 2 to 3 migration and GraalVM Native Image.

Technical choices

Tokenisation performance: network latency traced end to end in Dynatrace, microservices merged to remove intermediate calls, request-reply over Kafka replaced by direct HTTP calls, PostgreSQL indexes reworked.

Synchronous calls versus Kafka: an immediate response where Visa requires one, deferred processing for everything else.

Balance check between the bank, the card processor and Visa: investigation of response times and of the use of stand-in authorisation.

Java 21 · Spring Boot 3 · Kafka Confluent · Schema Registry · REST / OpenAPI · GCP / GKE and on-premises · ArgoCD · GitLab CI/CD · PostgreSQL · GraalVM · Datadog · Dynatrace

Method

How I work

The simplest solution that meets the time limit

In mobile payments: a synchronous response where Visa sets a response-time limit, Kafka for everything else. I choose what holds up in production.

New systems plug into what already exists

Mainframe, core banking, card processor: I integrate them through explicit, tested interface contracts.

No silent failures in production

Replay without duplicates, monitored dead-letter topics, alerts on failures: an error must be visible and recoverable.
