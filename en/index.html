A card, transfer or cheque transaction flagged as suspicious must be confirmed by the customer on their phone, then processed without delay.

  • Design and development, with the team, of the Java microservices behind this confirmation journey: Kafka flows with Avro contracts, REST APIs, mainframe exchanges; and later enhancements.
  • Error recovery without duplicate effects: Kafka retry strategy, replayable dead-letter topic and a step-tracking table. Each successful step is recorded and never replayed, so a replay never blocks a card twice.

  • Latency between the public cloud and on-premises: interconnect gateway and direct DNS resolution checked with the cloud network team.
  • Spring Boot 2 to 3 migration and GraalVM Native Image.

Applied AI

An incident-analysis agent, on a banking assignment

On my own initiative, using the AI tool approved on the assignment, I designed and rolled out an agent that a business analyst or a developer runs on demand. It cross-checks logs, tickets, monitoring and the registry of deployed images through MCP servers, and relies on the functional documentation.

  • Business analysts get a first diagnosis without pulling in a developer.
  • Developers get a fast, assisted first analysis of defects before fixing them.
  • Presented to other development teams.

Tools: the coding assistant approved for the assignment, in agent mode; MCP servers (code repository, tickets, documentation, logs, image registry)

“AI proposes, a person decides.”

The agent returns a diagnosis; the analyst or developer runs it and makes the call. Same principle in my own projects: when data is sensitive, the model runs locally.
